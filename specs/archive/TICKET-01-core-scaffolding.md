# TICKET-01: Базовый каркас, схемы и проверка работоспособности (Core Scaffolding & Healthcheck)

## Objective
Развернуть базовый фундамент мобильного портала «Цифровой деканат» на современном стеке Next.js 16 и Tailwind CSS v4, спроектировать реляционную схему данных с расширением `pgvector` и политиками Row-Level Security (RLS) в Supabase, создать набор реалистичных вымышленных сид-данных, разработать студенческие экраны и очередь сотрудника деканата, а также реализовать серверный маршрут AI-ассистента с векторным поиском регламентов и детерминированным оффлайн-фоллбэком.

---

## Preconditions
- Установленные Node.js v20+ и менеджер пакетов `pnpm`.
- Инициализированный Git-репозиторий с базовыми правилами AntiGravity.
- Локальная среда разработки с поддержкой TypeScript strict mode.

---

## Scope
1. **Каркас приложения и дизайн-система**:
   - Next.js 16 (App Router, Turbopack, React 19).
   - Tailwind CSS v4 с палитрой OKLCH и компонентами shadcn/ui.
   - Мобильно-ориентированная верстка (Mobile-first, корректное отображение от 360px).
   - Обязательный сквозной баннер-дисклеймер конкурса на всех страницах.
2. **База данных и схема безопасности (DDL)**:
   - Миграция `supabase/migrations/0001_init.sql`: 10 таблиц (`groups`, `profiles`, `lessons`, `lesson_changes`, `grade_records`, `requests`, `request_events`, `notifications`, `regulation_chunks`, `ai_messages`).
   - Расширение `pgvector` и функция семантического поиска `match_regulation_chunks`.
   - Строгие политики Row Level Security (RLS) для изоляции данных студентов.
3. **Генерация сид-данных**:
   - Скрипт `seeds/seed.ts` с вымышленными учетными записями: Студент 1 (отличник), Студент 2 (с задолженностью), Сотрудник деканата (модератор).
   - Расписание занятий на семестр с аудиториями и изменениями.
   - Оценки БРС, история заявок и 40 статей вымышленных регламентов университета.
4. **Академическая логика и тесты**:
   - Модуль `lib/academic.ts` с чистыми функциями расчета прогресса диплома, GPA и факторов академического риска.
   - Набор модульных тестов Vitest для проверки корректности алгоритмов.
5. **Пользовательский интерфейс**:
   - Студенческий дашборд (`/dashboard`): сводка успеваемости, индикатор риска, виджет расписания.
   - Расписание (`/schedule`): фильтрация по дням, бейджи замен и переносов.
   - Зачётка (`/grades`): баллы БРС, симулятор оценок.
   - Заявки (`/requests`): форма заказа справки, трекинг статуса в виде таймлайна доставки.
   - AI-ассистент (`/ai`): интерфейс диалога с регламентами.
   - Панель деканата (`/staff`): очередь входящих обращений с историей и модерацией.
   - Страница входа (`/login`) с карточками быстрого выбора тестовых пользователей.
6. **Серверный роут AI-ассистента**:
   - Эндпоинт `/api/ai/chat` с поддержкой семантического поиска фрагментов регламентов.
   - Детерминированный оффлайн-фоллбэк по ключевым словам со строгим цитированием номеров статей регламента при отсутствии внешнего AI API ключа.

- Публичный деплой и настройка HTTPS-домена на сервере (перенесено в TICKET-02).
- Подписки Supabase Realtime на веб-сокетах (перенесено в TICKET-03).
- Генерация скачиваемых файлов PDF со штампами (перенесено в TICKET-06).
- Оболочки Telegram Mini App и MAX Mini App (перенесены в TICKET-04 и TICKET-05).

## Done-When
1. `pnpm typecheck` выполняется без единой ошибки типизации.
2. `pnpm lint` завершается без предупреждений и ошибок.
3. `pnpm test` выполняет 6 юнит-тестов академической логики со 100% успехом.
4. `pnpm build` формирует оптимизированный производственный бандл.
5. Мобильный интерфейс проверен на ширине 360px: отсутствуют горизонтальные полосы прокрутки.
6. Дисклеймер конкурса отображается на каждом экране.

## Risks & Mitigations
- **Риск**: Утечка приватных данных одного студента другому через клиентский интерфейс.
  *Митигация*: Использование серверного клиента Supabase с проверкой RLS и изоляцией на уровне сессии.
- **Риск**: Падение AI-ассистента при отсутствии внешнего API-ключа OpenAI/OpenRouter во время проверки жюри.
  *Митигация*: Реализация надежного эвристического оффлайн-режима с поиском по локальному корпусу статей.
