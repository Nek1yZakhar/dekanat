# TICKET-08: Сборка конкурсного пакета и отчет PROCESS.md (Submission Package & Process Report)

## Objective
Сформировать исчерпывающий финальный пакет конкурсной заявки для жюри *MGIMO × AI Challenge*: составить и сверстать ключевой документ оценки — отчет о процессе разработки (`docs/PROCESS.md` $\to$ PDF), подготовить блок быстрого старта для жюри в `README.md`, составить покадровый сценарий видеоролика-демонстрации и провести итоговую комплаенс-валидацию по всем критериям регламента конкурса.

---

## Preconditions
- Успешно завершены и верифицированы все функциональные этапы (TICKET-01 — TICKET-07).
- Действующий боевой деплой с публичным HTTPS URL, доступный из РФ без VPN.
- Наличие всех скриншотов, диалогов агентов, логов тестов и истории коммитов.

---

## Scope
1. **Главный документ процесса разработки (`docs/PROCESS.md` $\to$ PDF)**:
   - Создание подробного, структурированного отчета по стандарту конкурса:
     1. *Проблематика и ценность для студентов*: детальное обоснование архитектуры портала (фрагментация расписания/зачеток/заявок по разным архаичным системам, отсутствие мобильного интерфейса, непрозрачность академического статуса и риска отчисления).
     2. *Стек ИИ-инструментов и сервисов*: полный перечень использованных технологий (AntiGravity 2.0, Claude 3.7 Sonnet / Gemini 2.5 Pro / GPT-4o, Perplexity Pro, Supabase MCP, Docker, Git) с указанием роли каждого инструмента.
     3. *Ключевые промпты и диалоги агентов*: фиксация эволюции промптов, демонстрация работы системы многоуровневых правил (`AGENTS.md`, `.agents/rules/specs.md`) и управления контекстом как доказательство высокой культуры Vibe-кодинга.
     4. *История визуального развития*: хронология интерфейса от первых набросков до релизного прототипа, включая отброшенные и неудачные варианты.
     5. *Архитектура безопасности простыми словами*: доступное объяснение авторизации, изоляции данных через Postgres Row Level Security (RLS), безопасного хранения ключей на сервере и работы нейросетевого RAG.
     6. *Вклад соло-автора (Захар)*: перечень ручных экспертных решений (дизайн-схемы, деплой на VPS, архитектурные решения, комплаенс-контроль).
   - Экспорт отчета в качественный представительский PDF-файл (`docs/PROCESS.pdf`) с оглавлением и векторными иллюстрациями.
2. **Блок «Для жюри» в корневом `README.md`**:
   - Размещение в самом верху `README.md` компактной памятки:
     - Действующая публичная ссылка на развернутый сервис.
     - Учетные данные 3 тестовых пользователей (Студент 1, Студент 2, Сотрудник деканата) с описанием их ролей.
     - Краткое описание концепта в 1 абзац.
     - Ссылка на видеодемонстрацию и PDF-отчет о процессе.
3. **Сценарий видеодемонстрации ($\le 5$ минут, вертикальный мобильный формат)**:
   - Покадровый тайминг презентации для смартфона:
     - `0:00–0:30`: Вход под отличником, обзор главного дашборда и индикатора риска.
     - `0:30–1:15`: Расписание на неделю, просмотр замены аудитории с бейджем.
     - `1:15–2:00`: Зачётка с баллами БРС и симулятором экзамена.
     - `2:00–2:45`: Заказ новой справки об обучении.
     - `2:45–3:30`: AI-ассистент: вопрос по регламенту с цитированием статьи.
     - `3:30–4:15`: Вход под сотрудником деканата: модерация заявки, перевод в «Готово».
     - `4:15–4:45`: Мгновенное получение уведомления студентом в Realtime и скачивание готовой PDF-справки.
     - `4:45–5:00`: Заключительный титр с дисклеймером конкурса.
4. **Финальный комплаенс-чеклист регламента конкурса**:
   - [x] Работающий интерактивный веб-прототип (не макет Figma).
   - [x] Полноценная адаптивность от 360px без горизонтальной полосы прокрутки.
   - [x] Исключительно вымышленные персональные данные и учебные записи.
   - [x] Сквозной дисклеймер концепта на всех экранах.
   - [x] Отсутствие реальных гербов, эмблем или печатей официальных вузов.
   - [x] Чистота лицензий шрифтов (SIL Open Font License) и иконок.
   - [x] Отсутствие секретов и API-ключей в репозитории и клиентских скриптах.
   - [x] Стабильная доступность из РФ без VPN.
   - [x] Публичный или открытый по ссылке репозиторий GitHub для жюри.
5. **Синхронизация `docs/CHANGELOG.md`**:
   - Фиксация всех тикетов (TICKET-01 — TICKET-08) в виде полноценных версий с перечнем возможностей.

## Risks & Mitigations
- **Риск низкой оценки за процесс**: В конкурсах по вайб-кодингу жюри часто оценивает культуру промптинга и прозрачность использования ИИ выше, чем просто готовый код.
  *Митигация*: Сделать отчет `docs/PROCESS.md` максимально глубоким, честным и наглядным, подчеркнув системную работу со спецификациями и правилами AntiGravity.
